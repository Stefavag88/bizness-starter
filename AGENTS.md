# Repository guidance

Use Node 22.x or 24.x and pnpm 10.13.1. Write project Markdown in English; keep public English/Greek strings localized. Read docs/QUICKSTART.md, docs/CONTENT_MODEL.md and docs/ARCHITECTURE.md before changing ownership boundaries.

Canonical content lives under content; settings own identity/contact/navigation, while Pages own page text and stable section instances. Translations supply copy by section ID and cannot independently change structure. Keep filesystem loaders out of browser/editor imports. Native validation must preserve the original editor AST and validate a detached projection.

Edit theme JSON and semantic component tokens, never generated CSS/registries, Tina output, manifests or generated Worker configuration. Use registered static section renderers and safe shared rich-text/link helpers. Protect required page regions and publication-derived locale alternatives.

Run focused regression tests for behavior changes, then pnpm check, pnpm test and appropriate build/browser checks. Native saves require the real UI and request/schema/installed-serializer-derived ownership; never restore unknown editor bytes. Stop the owned launcher before pnpm test, cms:local-build or test:profiles; the full suite owns a second Astro lifecycle instance. Use configured ports and stop only processes created by your command. Do not install/build/save in either read-only source repository.

Composition A enables explicit Standard draft creation, optional section add/reorder/remove and localized navigation authoring. Preserve immutable saved identity, required regions, canonical scalar types and native typed-copy aliases. Read docs/COMPOSITION_AUTHORING.md. Composition B adds FAQ, steps, media/text and gallery with stable nested IDs and safe original uploads. Composition C adds static domain extensions and optional Rooms (default disabled); read docs/DOMAIN_EXTENSIONS.md and docs/ROOMS_AUTHORING.md. Keep explicit config/type/content/Tina/Astro registrations separate; use keyed datasets and shared enquiry projection. Stop the owned stack before module configuration/CMS changes and restart after regeneration. Task reviews 1–7 and whole-branch review at 7a12969 are approved; final documentation scoped rereview and local closeout are complete. Stages 3/4, presets and destination initialization remain deferred. Sending, hosted providers, deployment and release tagging require separately authorized work.

The local-only design-system showcase uses detached fixtures and actual renderers; see docs/DESIGN_SYSTEM_SHOWCASE.md. URL preview choices never persist. Keep scripts/styles external under asset CSP. Stop the owned dev launcher before test:showcase-builds, which performs guarded staging/production exclusion and rebuilds exact-restored local configuration last. Never regenerate from a conflicted canonical file. Original starter-sample PNGs are ordinary reusable business media and remain in nonlocal builds; dedicated showcase JS/CSS must not. Keep source metadata decoding server-only and preserve exact owned fixture restoration.

Stage 4 presets and independent initialization are implemented on codex/starter-v2-presets; final whole-branch review is recorded with the dated initialization evidence. Read docs/PRESETS.md and docs/INITIALIZATION.md. Source-only /templates routes require the local marker and are excluded from client/nonlocal graphs. Maintain the explicit application export inventory when adding runtime files. Client presets reset all infrastructure and review flags; they are independent projects, not an in-place migration or update mechanism. Stop owned launchers before test:presets and standard lifecycle checks. Sending, hosted resources and production remain blocked as documented.
