# Website maintenance guidance

This is an independent business website. Use the actual local package scripts and schema contracts; source starter paths or past chat history are not dependencies. Read docs/CONFIGURATION_MAP.md and .agents/skills/starter-maintain-site/SKILL.md for prompt-driven changes. site:inspect reports current canonical owners and section choices without configuring or writing files.

Keep content in content/settings, content/pages, content/offerings, content/people and optional content/articles/domains. Settings own shared brand/contact/social/navigation/newsletter policy; Pages own typed section structure/visibility and localized copy by stable ID. Project settings own modules/profiles/interests and developer infrastructure. Theme JSON and semantic tokens own reusable presentation. Prefer existing settings; when a capability is absent, extend its typed schema, CMS fields, shared consumer and meaningful checks together. Never silently drop unsupported configuration or content. This independent app owns scripts/deployment/release-files.json, a hand-maintained source inventory: include new runtime components/scripts/fonts there unless already covered by automatic content/uploads/theme collection. It has no source initializer inventory; generated manifests remain off limits.

Saved IDs/slugs and section types are immutable; required hero/privacy content and Contact form stay protected. Keep translation structure shared and public copy localized. Use safe shared rich-text/link/media helpers. Preserve native rich ASTs and installed serializer contracts; do not restore unknown edited bytes. Work only in this app unless the human requests cross-project work. Keep project Markdown in English.

Use Node22/24 and pnpm10.13.1, frozen install and the scripts listed in package.json. Never edit generated theme CSS, .generated, Tina generated output or wrangler.generated.json. Stop only this app's owned launcher before module/configuration changes or full checks; configure regenerates outputs. Run focused tests, check, test and appropriate build/browser/native CMS checks. Avoid overlapping heavy installs with full suites. Restart through dev:cms after acceptance, using distinct ports for simultaneous projects.

Keep .env/.dev.vars and tokens out of source/CMS. Default sending, marketing and infrastructure are inert. Local tests or capture success do not authorize cloud provisioning, remote SQL, deployment or real sending. Follow docs/DEPLOYMENT.md, RELEASES.md and PRODUCTION_READINESS.md for those separately authorized tasks. Preserve unrelated edits; commit only the requested scope. Significant changes benefit from an independent final review; ordinary content/style requests do not require agent teams.
