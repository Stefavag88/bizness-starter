# Responsive media optimization

Stage 3A generates static responsive images for media/text, normal and featured galleries, Room cards and Room detail figures. Editors continue to select original local `/uploads/` files. Canonical records contain only `{src,crop}` and localized alt/caption copy; generated `/_media/v1/` URLs belong to render output and must never be saved by Tina.

## Developer policy and rebuilds

`project.json` may contain:

```json
"media": {
  "optimization": {
    "enabled": true,
    "widths": [320, 640, 960, 1440, 1920],
    "quality": 80
  }
}
```

Omitting the object uses these defaults. Widths must be ascending unique integers between 160 and 2560, with one through six entries. Quality must be an integer between 40 and 95. Unknown keys reject. These are developer configuration, outside the structural CMS descriptor. Stop the exact owned launcher before changing policy, run `pnpm configure`, then restart the launcher; deployed static output requires a new build. `enabled:false` preserves source safety checks and uses the original-image presentation without derivatives.

## Formats, dimensions and limits

The pinned Sharp 0.35.5 pipeline produces WebP plus original-format JPEG/PNG fallback; a WebP original uses one family. PNG fallback remains lossless with alpha. AVIF is deferred to avoid adding encoding cost without benchmarking. Animated/multipage files pass through unchanged with reason `animated-or-multipage`; this does not certify animation accessibility.

Source bounds remain 20 MiB, 20,000 pixels per side and 40 million pixels. Only contained regular PNG/JPEG/WebP files under `/uploads/` are accepted; one-decode path and symlink/reparse checks apply. The encoder consumes the exact validated Buffer snapshot. Corrupt referenced payloads fail with page/section/item/source context instead of silently substituting an original. Original files remain unchanged and public.

Widths are capped at the oriented source width and the largest configured width, deduplicated and sorted. There is no upscaling, at most six candidates per family/twelve outputs per source, and two concurrent transform jobs. Orientation is normalized before resizing. Heights are integer encoder dimensions, so aspect-ratio calculations can differ by a pixel after rounding. Crop remains CSS `object-fit:cover` and center/top/bottom positioning inside the existing fixed frames. Intrinsic dimensions, lazy loading, async decoding, alt and safe localized captions are retained. Room listing cards intentionally omit captions; Room detail figures retain them.

Small files and lossless fallback are exceptions to universal savings claims. Equal-dimension fallback can reuse original bytes when re-encoding would be larger. Browsers choose a candidate using viewport, DPR, format support and their own resource selection behavior; tests do not require an exact filename for every browser heuristic.

## Layout sizing is coupled to CSS

`packages/media/layout.mjs` derives `sizes` from the current 72rem wrap, symmetric `clamp(1.25rem,4vw,3rem)` padding, 17rem auto-fit minimum tracks and 2rem gaps. Media/text uses half the available width from 768px. Normal galleries and Room cards bound auto-fit columns by actual rendered item count. Featured galleries use the same auto-fit behavior below 768px, including at 640px; at 768px and above, the lead spans the full width and later items occupy half-width tracks. Room detail uses the 58rem editorial wrap. Density changes vertical spacing.

Changing those CSS widths/gaps/breakpoints requires updating the sizing policy and browser geometry assertions together. Acceptance compares actual frame width with the browser-evaluated `sizes` length within 1.1 CSS pixels, including neighbors around the two-column and featured breakpoints.

## Cache, delivery and ownership

The ignored `.generated/media-optimization/cache/v1` namespace is pipeline-owned cache, independent of canonical uploads and acceptance artifacts. Identities include validated source bytes, width/format/quality, Sharp/pipeline version and orientation/encoding policy. Cache reuse verifies identity, output hash and decoded dimensions; writes are atomic. Missing/corrupt entries can be regenerated by rendering/building the source again. Never clean original uploads to recover a cache, and never treat cache inventory as publication authority. Remove only the verified marked pipeline cache while the owned stack is stopped if a clean regeneration is needed.

Every build has its own demand session. Only variants requested by actual renderers are published into `apps/site/dist/_media/v1/`, even when a warm local cache contains showcase variants. Original starter-sample uploads are legitimate reusable business assets and remain public in staging/production. Local-only showcase route and dedicated preview code remain excluded outside local builds.

Astro development creates derivatives while rendering known content and serves only exact already-demanded identities through its contained adapter. Same-path changed bytes produce new identities. Upload add/change/unlink retains existing live behavior; a referenced missing source fails visibly. Static production delivery is ordinary built Worker assets under existing CSP. There is no Worker encoder, remote fetch or visitor-controlled width/quality endpoint. Unknown `/_media/` paths cannot generate files.

Storage and build work can grow: originals remain, fallback and WebP variants coexist, and the persistent cache survives builds. Smaller visitor transfers do not imply a smaller deployment or a faster cold build. A warm cache reduces repeated encoding, not the source safety checks.

## Verification and recovery

Use the installed browsers under `.generated/browsers`; these commands do not download browsers:

```powershell
pnpm test:media-optimization -- --pure
pnpm test:media-optimization -- --static
pnpm test:media-optimization -- --native
```

Run with the owned launcher stopped. Each phase retains separate command/PID/time/log records and full canonical snapshots under unique `.generated/media-optimization/acceptance-*` directories. Static/browser and native results are independent. Native tests own their indexed Tina/Astro children, derive complete expected documents and serialized bytes from actual intercepted requests plus installed schema/serializer before dispatch, and restore the original bytes/absence. Documents restore before dependent media; conflicts preserve unknown edits and refuse regeneration. No source D1 migration or sending is part of media acceptance.

The [acceptance evidence](superpowers/plans/2026-10-19-starter-v2-media-optimization-evidence.md) records exact tested combinations, candidate tables, transfer evidence, raw paths, failures, cleanup and limits. These checks cover the changed boundary; they do not certify every theme/density combination, browser engine, hosted provider or general accessibility compliance.
