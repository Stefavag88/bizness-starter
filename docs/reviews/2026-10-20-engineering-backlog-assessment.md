# Engineering backlog assessment

Date: 2026-10-20
Reviewed implementation: `3e2c7cb`
Repository: `C:/Projects/bizness-starter-v2`

## Conclusion

The submitted backlog mixes genuine behavior defects, intentional contracts, existing protections, unverified external prerequisites and optional platform improvements. It should not become 55 implementation tickets unchanged. In particular, the translated-slug, publication-inheritance, missing-settings, missing-translated-items, missing-theme-validation and public-manifest-exposure claims are not demonstrated defects in the supported current architecture.

The current configuration is local, enquiries-only, with sending disabled. No immediate exploitable P0 issue was established by this audit. This does not certify production readiness: hosted release remains deliberately blocked. Several confirmed defects affect the supported newsletter/nurture paths and must be resolved before those capabilities are enabled for real visitors.

Permanent bounce/complaint handling needs an explicit address-level suppression policy. Do not introduce a blanket generation filter that silently allows a new subscription to bypass an earlier complaint. Uncertain email outcomes must remain quarantined rather than automatically retried.

## Scope and evidence

Three independent read-only source reviews covered messaging, security/infrastructure and localization. The controller cross-checked shared boundaries, architecture, tests and priorities. Existing tests were freshly executed with:

```powershell
pnpm exec vitest run tests/lifecycle.test.ts tests/backend-profiles.test.ts tests/access-roles.test.ts tests/security.test.ts tests/publication.test.ts tests/localization.test.ts tests/manifest.test.ts
```

Result: **7 files, 82 tests passed**. Detached pure-function checks reproduced the accepted-origin trailing-slash URL bug and confirmed rejection of translated slugs and incomplete translated item membership. Existing passing tests are evidence of current contracts, not proof that untested concurrency/provider failure paths work.

No production code, canonical content, configuration, runtime processes or hosted resources were changed. No cloud credentials were inspected or external configuration verified. The source-derived concurrent-signup failure path needs a targeted reproduction before implementation. Source references below are relative to this repository and refer to the reviewed revision.

## Recommended course of action

1. **Correctness batch:** fix URL construction (#22), validate combined contact/signup input before persistence and define durable opt-in handling (#4), reproduce and fix signup identity/retry races (#20), isolate scheduled tasks (#8), classify malformed webhook input correctly (#19). Add focused failure tests with each fix.
2. **Newsletter/nurture delivery batch:** distinguish pause from cancellation (#11); reconcile Workflow terminal states (#7/#16); define feedback policy/provenance/idempotence (#1/#15/#21/#31); narrow final-send eligibility races (#14); review provider error codes without weakening uncertain-outcome quarantine (#13).
3. **Hosted release batch:** isolate deployment identities and resources (#3/#23/#43), support versioned migrations before introducing schema changes (#35), implement real hosted Tina/Access and Turnstile integration, configure/test SES/SNS and secret bindings (#9/#25/#28/#29), establish retention/recovery procedures (#12/#27/#55), and connect verified release checks to CI (#2/#32/#46/#48). Keep production blocked throughout incomplete prerequisites. Any schema-changing work from batches 1–2 must bring migration support forward first.
4. **Operational visibility:** build on existing job IDs and overview for investigation, metrics and alerts (#12/#51–#55). Begin with a runbook and protected actionable JSON; build a larger dashboard only when operators need it.
5. **Later platform improvements:** central capabilities, build locking, configuration upgrades, linting, optional infrastructure and performance work. Avoid splitting the Worker or adding a complex plugin framework for this backlog.
