# Create a business website

Use the actual initializer, not a repository clone or copied legacy backend. Read AGENTS.md, docs/INITIALIZATION.md and docs/PRESETS.md, then inspect current scripts and initializer help. Names/folders use lowercase technical identifiers; display branding belongs to Settings. Preserve the requested name, languages, reference design and destination. Confirm missing consequential choices; infer routine choices from the request and record assumptions.

Run the supported create:project command with --dry-run before the same actual command. An occupied destination is a refusal, not permission to delete it or invent --force. A partial destination belongs to that attempt and may contain competing changes; preserve it and report the exact problem. The initializer creates Git but does not install, configure hosting or start services.

In the new app, read its generated AGENTS.md, docs/CONFIGURATION_MAP.md and starter-maintain-site skill. Use frozen install and the app's actual check/test/build/worker:check scripts, then site:inspect. Confirm all migrations, independent runtime imports, inert infrastructure/review flags, client-specific guidance and absence of source preset tools. Run full suites and heavy isolated installs sequentially on a constrained machine; stop only owned launchers as the app's instructions require.

For an existing design reference, inventory routes, translations, content, theme/font/media ownership and configuration gaps. Keep the reference read-only. Convert content through a repeatable validated one-way migration into the destination and report unsupported fields; preserve stable URLs/relationships. Extend shared typed presentation contracts when the current model cannot express the approved result. Add new runtime components/scripts/fonts to the destination release inventory; source-starter changes also require its initializer export inventory. Content/uploads/theme directories are automatically collected, but other new files are not. A neutral scaffold is not proof of visual parity. Never copy generated editor/theme/manifest/config files, old runtime databases, secrets or the old backend.

Use independent configured ports for simultaneous apps and restart with the owned launcher. Verify relevant browser/native CMS behavior; do not save unknown editor bytes. Preserve user changes and report verification and remaining launch gates. Initializing or developing a website does not authorize remote SQL, deployment, provider sending, resource creation or credential storage. Use existing production preparation/release safeguards when separately requested.
