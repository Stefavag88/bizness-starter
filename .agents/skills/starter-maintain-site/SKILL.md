# Maintain a business website

Read this app's AGENTS.md and docs/CONFIGURATION_MAP.md, then run site:inspect if its current canonical content is valid. Inspect the relevant current schema/component before selecting an owner; the report identifies available choices, not an exhaustive semantic interpretation of the request. Existing authorization carries forward; ask only for missing information that affects scope or outcome.

Prefer the existing canonical owner. Page-specific surface/visibility/order/copy belongs to that Page and stable section ID; translation copy does not own structure. Shared identity/phone/social/navigation/newsletter policy belongs to Settings. Theme JSON controls shared semantic colours/tokens. Profile/modules/interests are developer-owned project settings. Generated CSS, generated manifests, Tina output and Worker config are outputs, never editing sources.

For 'lighter section', identify that page/section and inspect the current theme before choosing default/muted/accent: their names do not guarantee brightness. For 'hide team', disable the requested people-list instance and retain records/copy. For 'phone everywhere', change shared contact.phone, then check authored tel links/prose for real duplicates without blindly replacing numbers. Preserve navigation order/labels when changing its saved Page relationship; immutable saved IDs/slugs require a separately designed migration.

For newsletter footer requests, use the shared experience/form. Inspect profile, modules.newsletterPrompt, project.interests, Settings newsletterPrompt and published Privacy pages. Footer inline does not implicitly authorize disabling an existing modal. Existing policy/copy/timing stays unless requested; add complete localized inline/consent/success text. Enquiries cannot expose signup until its developer-owned feature prerequisites change. Capture/protection/delivery readiness and consent remain separate; a feature toggle never grants real-sending authorization.

If existing settings cannot express the request, explain the missing capability and extend the typed schema, native CMS fields, shared renderer/consumer and tests together. Do not invent arbitrary CSS overrides, hidden config keys or business-specific exceptions to bypass validation. Keep unrelated presets/sections unchanged. Hand-maintained runtime inventories are source configuration, not generated manifests: adding runtime components/scripts/fonts outside automatically collected content/uploads/theme folders requires updating scripts/deployment/release-files.json. Independent clients maintain that inventory only; in the source starter also update scripts/initialize/export-manifest.json. Use the inspector inventories report to distinguish them. Reuse safe rich-text/link and media helpers; preserve required Hero/Privacy/Contact capabilities and original editor ASTs. Read-only inspection is safe; native saves must use installed request/schema/serializer ownership and preserve unknown bytes on conflict.

Run the focused meaningful checks for the changed owner, then appropriate app checks/build/browser verification. Stop the owned launcher before configuration/module changes or full suites, regenerate through configure, and restart after acceptance. Do not run a heavy isolated install alongside the full suite on a constrained machine. Inspect both languages/mobile where relevant, plus native editor reload after CMS changes. Report what changed, where values come from and evidence; do not claim hosted readiness from local checks. Deployment, remote migrations, secrets and real sending remain separately authorized through documented release gates.
